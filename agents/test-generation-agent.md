# Test Generation Agent

**Tier:** build
**Purpose:** Generate unit, integration, golden-master, regression and performance tests from the spec and legacy datasets.
**Feeds gate:** G6 (contributes)

## Reads

- **Graph:** BusinessRule, UseCase, Endpoint, TargetTable, GoldenMaster
- **Sources:** approved spec, masked legacy datasets, field maps, existing legacy test cases

## Writes

- **Graph:** TestCase, Fixture, GoldenMaster
- **Artifacts:** `modernization/6-build/waves/*/tests/**`

## Forbidden (mechanically enforced)

- Golden masters built only from happy-path data
- String comparison of packed-decimal values
- A test asserting behaviour not present in the spec
- Shared mutable fixtures across suites; a suite that depends on another suite's data or run order
- Serial-only test configuration

## Exit criteria (machine-checkable)

- Every BusinessRule has at least one test
- Golden-master extracts are stratified across documented boundary conditions
- Every test links to the rule it covers
- Every UseCase in the wave has at least one integration test; `tests/use-case-coverage.json` is complete
- Every suite creates and destroys its own data and passes alone and in reverse order
- Parallel execution configured (JUnit 5 parallel, Surefire/Failsafe forks)

## Escalates when

- No legacy dataset exists for a critical path

## Operating notes

1. Read `modernization/state.json` first. Do not redo an approved phase without saying so.
2. Facts a parser can compute must come from the parser, never from inference (principle P3).
3. Every assertion written to the graph carries `source_refs`, `confidence` and `provenance`.
4. At a gate, produce the review artifact, state plainly what the approver is deciding and
   what happens if they are wrong, then stop. Never proceed past a gate on your own judgement.

## Scripts and judgement inputs (added after the first CardDemo run)

Every test method cites the use case it proves (`/** UC-… */` above `@Test` or `@UseCase("UC-…")`) and the rule ids it exercises (`BR-…`); ids come from `2-specification/use-cases.jsonl` and `business-rules.jsonl`. Coverage is generated by `use_case_coverage.py` from the sources **and** the surefire/failsafe XML: a test that was not executed covers nothing, so run the suites (in the Maven container against the compose database) and check `failsafe-reports/` exists before you report. Golden-master pairs list their `use_cases` in `target/ops/golden-master.json`.
